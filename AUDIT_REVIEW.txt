```python
def hidden_mse(
    student_h: torch.Tensor, teacher_h: torch.Tensor, proj: nn.Linear
) -> torch.Tensor:
    s = proj(student_h.float())
    t = teacher_h.float().detach()
    n = min(s.shape[1], t.shape[1])
    return F.mse_loss(s[:, :n], t[:, :n])
```

- Parent dim: parent.config.hidden_size (SmolLM-135M, valeur exacte NON TROUVÉ)

**d. Formules exactes de la loss**
Extrait distill.py:57-73:
```python
t = self.temperature
s_logp = F.log_softmax(student_logits / t, dim=-1)
t_prob = F.softmax(teacher_logits / t, dim=-1)
term = t_prob * (t_prob.log() - s_logp)
kl = torch.where(t_prob > 0, term, torch.zeros_like(term)).sum(dim=-1).mean() * (t * t)
ce = F.cross_entropy(student_logits.reshape(-1, student_logits.shape[-1]), targets.reshape(-1))
loss = self.alpha * kl + (1.0 - self.alpha) * ce
```
- KL: moyenne sur les TOKENS (B*S), pas batchmean
- CE: cross-entropy standard
- Pondération: alpha * KL + (1-alpha) * CE
- Température: T² appliqué à la KL (T² multiplie le résultat)
- Valeurs par défaut: alpha=0.7, temperature=2.0

**a. STE et calcul de l'échelle**

```python
def absmean_scales(w: torch.Tensor, group_size: int = 64) -> torch.Tensor:
    groups = w.view(*w.shape[:-1], -1, group_size)
    return groups.abs().mean(dim=-1).to(torch.float32)
```
- Scale: absmean par groupe (pas absmax)

Extrait quant.py:99-109 (activations):
```python
def quantize_activation_int8(x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
    amax = x.abs().amax(dim=-1, keepdim=True).to(torch.float32)
    scale = (amax / 127.0).clamp(min=1e-8)
    q = (x / scale).round().clamp(-128, 127).to(torch.int8)
```
- Activations: int8, scale absmax par ligne (par token)

## ANGLES MORTS

Ce que je vois de louche qui n'a pas été demandé:

1. **Pas de grad norm logging**: en distillation avec STE, c'est critique pour détecter les gradients explosifs/évanescents. Le grad clipping est là mais sans monitoring.

2. **Cache top-k désactivé dans tranche00**: config.json dit "aucun (parent en direct : cache k32/k64 sous-performe en val, +86 %/+17 % d'ecart, valCE 1.14/1.06 vs 0.80)". C'est un problème sérieux non résolu - le cache dégrade la performance de manière significative.

3. **Pas de baseline fp16**: impossible de comparer la performance réelle de la quantification 2 bits vs un modèle fp16 de même taille.

4. **Vocab parent inconnu**: la taille exacte du vocabulaire SmolLM-135M n'est pas documentée clairement (cosmo2-tokenizer taille non affichée sur HF).

5. **Pas de vérification de chevauchement éval/train**: eval_ppl.py exclut par normalisation mais ne vérifie pas par hash de documents, ce qui pourrait laisser passer des variations subtiles.

6. **Swap actif sur la machine**: 3.3M swapins / 4.7M swapouts - la machine est sous pression mémoire pendant l'entraînement, ce qui pourrait affecter les perfs.

7. **GradScaler absent**: en fp16 sur MPS sans GradScaler, l'underflow est possible même si le code a un garde-fou loss non finie.

8. **Licence manquante**: le repo n'a pas de fichier LICENSE, alors que le parent est Apache 2.0 - question de compatibilité.
